# Hivelet — project rules

Apartment management for the **Fe Galang Da Silva Boarding House**. Bicol University, IT 124
Capstone Project 2. Vue 3 + TypeScript, Express + TypeScript, Supabase PostgreSQL.

**The database is LIVE.** It holds the owner's real financial records — **952 live income rows and
1,370 expense allocations on 13 Oct 2026** (the paper's 937 and 1,327 are what was transferred from
her workbook; August came in on 30 Sep), **33 units, 32 of them occupied.** There is no staging
copy. She runs her business on this.

---

## Five rules that do not bend

1. **Never drop, wipe, truncate, or "reset for a clean test".** Every change to the schema **or
   to live data** is a **new numbered migration** in `database/migrations/`. Never an ad-hoc
   `UPDATE`. **Check `database/migrations/` for the highest number and go one past it** — a literal number here goes stale the first time anyone adds one. Run `npm run backup` before the first data change of a session.

2. **Never edit `database/FULL_DATABASE_SCHEMA.sql`.** It does not describe this database and has
   been wrong about it repeatedly — the property area type, which indexes exist, generated
   columns, foreign key actions. **Six of eight wrongly-recorded business rules took their
   evidence from that file.** Ask the catalogue instead: `information_schema`, `pg_index`,
   `pg_constraint`, `pg_trigger`, `pg_proc`. `database/live_schema.csv` has also been wrong.

3. **Verify before you report, and say what you verified against.** "It typechecks" is not
   verification. `vue-tsc --noEmit` exits 0 on a component that does not exist — tested, not
   assumed.

4. **BR-035 wording is locked.** `fifty_percent_share` is described **only** as a system-computed
   figure equal to half that row's Rent Amount, kept for ledger parity with the owner's
   historical spreadsheet. Never name a party, recipient, purpose or destination for it.

5. **Adyen with GCash is committed, configured and working.** The words `"mock"`, `"simulator"`
   and `"pending consultation"` must never be applied to the gateway.

**Two standing facts** documents here have been wrong about: the property is **33 units, not
32** (32 of them currently occupied), and no `"2% annual increase"` rule exists — the owner sets
rates by hand and only the change history is kept.

`npm run check:canon` fails the build on rules 2, 4, 5 and both standing facts.

## Verifying

```bash
npm run check:all 2>&1 | grep -E "^  (pass|FAIL)"
```

**Read the summary table, not the tail.** `| tail` shows the end of whichever suite ran last, and
a red check has been committed past that way twice.

Twenty-one suites (`check:concurrency` added 12 Oct 2026). **14 run on a bare clone**; **18** with `.env`; **all 21** with the backend up
(`npm run dev:backend`) and `credentials/creds.txt`. Both of those are gitignored and must be
sent separately — they never come down with a pull.

`check:liveness` runs 4 of its 7 rules without a backend and **still exits 0**, printing `note:`
lines about what it skipped. Read the notes, not the exit code.

## Before changing something that looks wrong

**Read `docs/13_AUDIT_JUDGEMENT_LOG.md` § 3 first.** Several things that look like bugs are
deliberate and say why: bills raised on demand rather than by a scheduler, the receipt guard
being code-only, Linda excluded from grand totals, the lockout message that enumerates accounts.
Section 2 has the defect classes worth re-running, and the recurring lesson is worth stating
here:

> **A comment explaining why something is safe encodes a precondition.** When the code around it
> changes, the precondition can fail silently and the comment will keep asserting the conclusion.
> Read them as claims with a date on them, and check the date.

## Working here

- **Two machines share this repository.** Pull before you start and before every push. Lanes:
  `backend/src/` and `database/migrations/` on Sean's side, `docs/` and `frontend/src/` on the
  other.
- **The Adyen webhook serves production.** Since 2026-09-24 it points at
  `https://hivelet.vercel.app/api/public/payments/adyen/webhook`. **Never repoint it at a laptop
  tunnel** - that silently stops the live site recording payments. To test locally, add a
  *second* webhook in Adyen with its own HMAC key. **Never generate a new HMAC key** on the
  production webhook without updating Vercel's `ADYEN_HMAC_KEY` and redeploying in the same
  sitting: Adyen keeps its own copy to sign with, so a different value makes every notification
  fail signature verification, which looks exactly like a broken integration (B-68).
- **Commit in small pieces with real messages.** The history here is the reasoning and is worth
  more than the diff.
- **Never stop because something is out of reach.** Record it in `BLOCKED_FOR_SEAN.md` with
  enough detail to act on cold, and move to the next thing.
- **Mutation-test a new check**: break each shape it claims to catch in a real file, confirm it
  fails, and revert in a `finally`. A check that has never failed on purpose has not been
  verified.
