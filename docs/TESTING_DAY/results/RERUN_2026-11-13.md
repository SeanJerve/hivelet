Of the 37 test cases the 4 November re-run left for a person (`RERUN_2026-11-04.md`), four need no
person and were run on 13 November, together with all 21 automated check suites. Nothing was written
to the live database.

## The automated check suites

`npm run check:all` in the main checkout, with `.env`, `credentials/creds.txt` and the backend
running (`npm run dev:backend`): **all 21 suites passed** (summary table read, not the tail).
Among them: `check:reports` 570 passed, 0 failed; `check:api` 78 passed, 0 failed, one SKIP (no other
tenant's ticket to probe with); `check:relations` 38 passed; `check:concurrency` 32 passed, with its
two expected notes (a receipt with no invoice number, or an acknowledgement receipt, sent twice at
the same instant saves twice, which the index exempts on purpose, B-105). `check:liveness` printed
one note: no "PN/mo" headline on the public page, so nothing to compare.

- **PF-01**, and PF-06's "cache cleared": this browser's cache cannot be cleared from a script, so
  a truly first load needs a private window.
